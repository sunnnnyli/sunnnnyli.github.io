NYC OTI, Jul 2025 – Aug 2026

Vulnerability Management Case Automation

The problem

Each of the 10 analysts on the vulnerability management team spent about 15 hours a week making PDF notices and emailing agencies by hand. The team named that work as one of the reasons people left.

What I built

Apex and Flow automation that turns case data into a one-page Visualforce PDF, attaches it to the case, and emails each affected agency its CVE details. Alongside it, a parent/child case pipeline that splits the master vulnerability CSV into agency-scoped files, attaches each one to its child case when the parent is approved, and sends remediation notices to the people who need them.

The result

About 150 hours a week given back across the team, roughly 15 per analyst.

  • Apex
  • Flow
  • Visualforce
  • Salesforce

Olympix, Sep 2024 – May 2025

Bug PoCer: Web3 Exploit Automation

The goal

Automate the slow, manual part of smart-contract audits: writing a working proof-of-concept exploit for a suspected bug.

What I built

A multi-agent AI pipeline I designed, with ideation, exploitation, output-parsing, and failure-feedback agents run by a status-driven orchestration loop. When an attempt failed, compiler errors and static-analyzer output were fed back into the next one. I learned C# on the job to port the system from Python into the company's codebase, and built an agent template so a new agent only needed a role. A Forge harness tested every generated exploit at runtime against a corpus of 20–30 Solidity contracts.

The result

The pipeline independently reproduced a documented exploit behind a $10K loss, confirmed against the published proof of concept.

  • Python
  • C#
  • Solidity
  • Forge
  • OpenAI API

NYU, Team project, Jan – May 2025

Journal Editorial Management System

A collaborative editorial platform for managing manuscripts through review, built as a team at NYU.

I also built the login flow and landing page, with Jest and React Testing Library component tests, shipped through a branch-and-merge workflow to a deployed Heroku app.

About this site

How this site is built

By hand

Plain HTML, CSS, and JavaScript that I write myself: no framework, no build step, and no trackers. GitHub Pages serves it straight from the repository.

Type

Newsreader for reading, Instrument Sans for labels, and JetBrains Mono for the diagrams. The proverb is set in Ma Shan Zheng, cut down to just the characters it needs, so it loads in a blink.

Motion

Scroll effects run on the browser's own scroll-driven animations where it has them, and page and theme changes use view transitions. All of it follows your reduced-motion setting, and the pause button in the top bar turns it off.

For everyone

Contrast follows your system too, with a button for more. Everything works from the keyboard (Ctrl+K, or ⌘K on a Mac, jumps anywhere), and the site keeps a copy of itself so it opens fast and still works offline.

Checked on every update

Each update runs automatic checks for broken links and for Lighthouse's accessibility, best practices, and SEO scores. The source is on GitHub.
